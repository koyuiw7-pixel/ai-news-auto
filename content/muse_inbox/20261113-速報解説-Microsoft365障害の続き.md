## 復旧の時期はまだ示されていません

Microsoft 365の障害は、2026年11月13日3時26分の発生から半日以上が過ぎた15時時点でも続いています。15時 − 3時26分 = 11時間34分が経過した計算です（サイソク編集部の計算）。メールソフトのOutlookや会議・チャットのTeamsなどがつながらない、またはつながりにくい状態です。

NHKによると、障害はアメリカや日本などの広い範囲で影響が確認されていて、復旧の見通しは不透明な状況です。マイクロソフトは復旧作業を続けていますが、完全復旧の時刻は公式に発表されていません。

## 使えない・使いにくいのはこのサービスです

マイクロソフトの公式の障害情報で、影響を受けているとされているのは次のサービスです。

- Exchange Online（Outlookのメール基盤。メールの送受信やメールボックスの表示ができない場合があります）
- Microsoft Teams（チャット、会議、通話が使えない、または不安定な場合があります）
- SharePoint Online（ファイルの共有や社内サイトの表示）
- Microsoft Copilot（Microsoft 365）（AI機能の呼び出し）
- Microsoft Defender XDR（セキュリティ管理側の機能）
- Microsoft 365 suite（各サービスの入口になる画面まわり）

障害の番号は、メール側がEX1550543、サービス全体がMO1550821です。職場や学校の情報システム担当へ問い合わせるときは、この番号を伝えると話が早くなります。

## 自分は対象か、の見分け方

仕事や学校でMicrosoft 365のアカウントを使っている人は、ほぼ全員が対象になり得ます。「自分のパソコンやネット回線の故障ではないか」と迷ったときは、次の順で切り分けてください。

1. スマートフォンなど、別の回線・別の端末からOutlookやTeamsを開いてみる。それでもつながらなければ、自分の環境ではなくサービス側の問題の可能性が高いです。
2. 公式のステータスページ（status.cloud.microsoft）で、障害が出ているか確かめる。
3. 組織の管理者権限がある人は、Microsoft 365 管理センターの「正常性」に、番号EX1550543とMO1550821の障害が表示されているか確かめる。

## なぜ起きたか、公式と報道が伝えていること

マイクロソフトの公式の障害情報では、複数のサーバーが予期せず利用できなくなり、残りの設備に負荷が集中したことが出発点とされています。復旧したサーバーが通信を受けると再び応答しなくなる事態も起き、通信の種類を一時的に絞りながら段階的な復旧が試みられてきました。

テレビ朝日が報じたところでは、マイクロソフトは当初、サーバーの再起動で「良い結果」が出ているとしていましたが、その後、こうした復旧策が「想定通りに効いていない」と明らかにしました。通信の振り分けの偏りが続いていて、処理能力を増やすための別の方法を探っているということです。

FNNが報じたところでは、13日午前11時半の時点でも完全復旧はしておらず、政府の情報システム基盤（GSS）でも支障が生じています。マイクロソフトは「可能な限り代替ルートに切り替え、限定的に復旧を確認している」としている、とFNNは伝えています。

公式の障害情報の14時台の更新でも、状態は「サービスの低下」のままでした。トラフィック急増の原因の特定とサーバー復旧に向けた複数の対策を並行して進めているとし、現時点で悪意ある活動（攻撃など）は確認されていないとしています。緩和が完了したあとには、原因や対策をまとめた事後報告書を公開するとしています。

## 今やること、しのぎ方です

復旧はマイクロソフト側の作業を待つしかありませんが、その間の仕事や連絡は次の方法でしのげます。

- 急ぎの連絡は、メールではなく電話や、組織の外のチャット手段に切り替える。FNNが報じたところでは、政府も電話・チャットツール・ショートメッセージなど複数の手段を確保して対応していて、企業でも受注作業をチャットに切り替えた例が出ています。
- 会議が開けない場合は、開始前に参加者へ「Teamsがつながらない場合は電話会議や延期に切り替える」と一報入れておく。
- 送ったつもりのメールが下書きや送信トレイに残っていないか確かめる。復旧後にまとめて送信される場合があるので、二重に送らないよう注意してください。
- 編集中の文書は、クラウドへの保存ができていない場合があります。手元の端末に別名で保存しておくと、復旧後の上書き事故を防げます。
- 短い間隔で再接続を繰り返すと、復旧途中の設備に負荷がかかる場合があります。公式ステータスの更新間隔に合わせて、少し時間を置いて確かめるのが無難です。

## 復旧の見込みは「未発表」です

完全復旧の時刻は、公式にも報道にも出ていません。テレビ朝日が報じたとおり、復旧策が想定通りに効いていない段階で、マイクロソフトは処理能力を増やす別の方法を探っています。一部地域で回復が見られるという公式の更新はありましたが、「完全復旧には至っていない」とされています。

復旧を待つ間に確かめるべきは、公式ステータスの状態表示です。「サービスの低下」から変わったかどうかが、復旧の進み具合を見る一番確かな目安になります。

## 公式の窓口と確かめ方

- Microsoft 365 サービス正常性ステータス：https://status.cloud.microsoft （障害の有無と対象サービスを確認できます）
- Microsoft 365 管理センターの「正常性」：管理者アカウントでサインインし、「正常性」→「サービスの正常性」の順に進むと、障害番号EX1550543とMO1550821の詳細と更新履歴が見られます。手順はMicrosoft Learnの「サービス正常性を表示する」（https://learn.microsoft.com/ja-jp/microsoft-365/enterprise/view-service-health）に載っています。
- 職場・学校のアカウントの場合は、まず自分の組織の情報システム担当へ。全体の復旧はマイクロソフト側の作業になるため、個別の問い合わせで早まるものではありません。

## サイソクの見方

今回の障害で実務上いちばん困るのは、メールと会議とファイルが同じ基盤の上に乗っているため、1つの障害で連絡手段がまとめて止まる点です。公式の障害情報にある対象サービスは6つで、そのうちExchange Online、Teams、SharePoint Onlineの3つは、日常の連絡・会議・資料共有そのものです。

判断の目安は次のとおりです。今日中に結論が要る連絡なら、復旧を待たず電話など別の手段に切り替えるのが安全です。明日以降で済む手続きや社内の定型連絡なら、公式ステータスの状態が「サービスの低下」から変わるのを確認してから動いても遅くありません。攻撃の可能性については、公式の障害情報が「現時点で悪意ある活動は確認されていない」としているので、不審なメールへの警戒を強めるよりも、復旧をかたった偽の案内メールにだまされないことのほうが大切です。
