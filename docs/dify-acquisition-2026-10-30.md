## 48時間・7日の判断基準

起点T0は「最終コミットの本番公開と基本確認が済んだ時刻」とし、T0 = 2026-10-30 14:38 JST。T0+48時間 = 2026-11-01 14:38 JST、T0+7日 = 2026-11-06 14:38 JST。公開前の日付を起点にしない。

**48時間で判断すること**

1. 2 URLが正しい内容で取得可能か、内部リンク・canonical・index許可・サイトマップ・表示・計測に障害がないかを確認する。故障や事実誤りは母数を待たず修正する。
2. GSCは最新の完全な対象日までで検索表示・URL状態を確認する。未クロールや未反映なら発見経路を確認し、同じURLの申請を連打したり記事を増やしたりしない。
3. 監視は初回基準と、その後の取得が継続したかを確認する。変更がなければ候補0が正常であり、公開本数を増やす必要はない。
4. 実訪問・導線遷移があれば記事別・流入元別に記録する。検索流入0や申込0だけで需要なし・失敗・達成見込みを断定しない。

**7日で判断すること**

| 観測された状態 | 次の行動 |
|---|---|
| 取得・インデックス・計測に障害 | 内容の需要評価より先に障害を直す。計測不能の期間を評価分母から外す |
| 表示された検索語が記事の疑問と違う | 検索語と回答の対応を確認し、同じURLの冒頭・見出し・対象読者を修正。無関係な語へ広げない |
| 関連する表示があるが訪問が少ない | 掲載順位・端末・検索語をそろえて確認。小さい母数でタイトル効果を断定せず、誇張せずに回答の具体性を上げる |
| 訪問があるが比較導線に進まない | 記事だけで解決した可能性を含めて確認。比較が必要になる箇所に自然な案内があるかを見直す |
| 無料Cloud・手元PCへの選択が多い | その選択を尊重する。VPSへ誘導を強めず、無料利用者の実際の疑問を既存記事で解決する |
| 有料先への遷移があるがASP発生0 | 提携条件、対象プラン、計測の範囲と欠測、クリックからの経過時間を先に照合。増量だけで解決しようとしない |
| 発生あり・未承認 | ASPの条件と約30日の目安に照らして保留。7日で否認や確定収益と扱わない |
| 検索・訪問の観測が少ない | 判断保留。公開期間、発見状態、関連性のある既存リンクを確認し、次の観測日と不足する分母を記録する |

最少観測の扱い（暫定の運用基準であり、統計的な有意性や達成目標ではない）:

- 検索CTRの改善判断は、記事ごとに関連クエリの100表示未満なら保留。100以上でも順位・端末・クエリ構成が違えば単純比較しない。
- 読後の比較導線は、対象記事で計測可能な実訪問が30未満なら割合の良し悪しを保留。30以上でも傾向を調べる段階で、成約率を確定しない。
- 入口記事の閲覧は既存funnel専用イベントにはない。記事別のWeb Analytics等で対応する分母を取得できない場合、`guide_click` だけから遷移率を作らず保留する。日別推定人数は期間をまたいで足してユニーク訪問者と呼ばない。
- ASP承認率は、成果条件に該当し判定期間が十分経過した発生だけを対象にする。未判定を否認へ入れない。分母不足なら予測を更新しない。

48時間・7日は「その日まで待つ」という工程ではない。誤り・故障・条件変更は分かり次第直す。需要や反応が不足している間も、公式差分の確認、出典の更新、関連する既存記事からの自然な導線、検索語と回答の照合は前倒しする。新規テーマの拡張は観測された疑問を根拠にし、量産で不足を埋めない。
