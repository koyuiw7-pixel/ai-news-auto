# Dify検索入口とA8記事別成果の識別

2026-10-30。目的は、Difyの疑問に答える記事から比較へ進んだ経路を、A8の成果帳票でも分類できるようにすること。自己広告クリック・自己成果は作らない。実装・テスト・本番反映・読者獲得・ASP発生・ASP確定は別の状態として扱う。

## 範囲

- 費用ガイドと起動ガイドの本文末・フッターの比較リンクに、固定値の `sa_from` を付ける。Next Linkのpropsに設定し、クライアント遷移でも残す。他ページのフッターリンクは元のまま。
- `/choose/dify-hosting` のXServer VPSだけ、表とカードの計2か所へ公式の `id1`〜`id3` を追加する。SSRは元URLのまま。ブラウザの準備後、DNT/GPC・自動ブラウザ・既知ボットに該当しない場合のみ分類を追加する。
- 無料Cloud、手元PC、他の商品、他ページの広告は対象外。元のa8mat、遷移先、符号化、fragment、画像の計測タグ、PR表記、relを保持する。設定元の `affiliate_links.json` は変更しない。
- Cookie・sessionStorage・localStorage、新たな通信や個人IDは追加しない。送る分類は短い固定英数字のみ。検索語・個人情報・参照元URL全文は送らない。
- 既存のid1〜id5があるURLや未確認形式は改変せず元リンクを使う。ページ移動・戻る・query変更・アンマウントでは自分が書いた値だけを元へ戻す。計測失敗でリンク操作を妨げない。

公式仕様：[パラメータ計測ガイド](https://support.a8.net/a8/as/faq/manual/a8-parameter-guide.php)。公式機能はAmazon・楽天のリンクへ流用しない。本変更はユーザーの「記事別にA8の発生・承認まで追える計測を強化」の指示に基づく限定例外。

## 分類表

| 項目 | 固定値 | 意味 |
|---|---|---|
| id1 | difyfree | `/guides/dify-free-api-cost` に設置した比較リンクの分類 |
| id1 | difystartup | `/guides/dify-1-18-startup-check` に設置した比較リンクの分類 |
| id1 | direct | 比較ページへ外部から直接来た、または参照元がない。アドレス直接入力だけを意味しない |
| id1 | internal | 同一サイトの別ページが参照元 |
| id1 | unknown | 不正・空・重複したsa_from等、判定できない経路 |
| id2 | difyhost | この比較導線 |
| id3 | table / cards | PC等の比較表／スマートフォン等のカード |

queryがない場合は参照元からinternal/direct/unknownだけを判定する。SPAではdocument.referrerが直前ページを表さないため、参照元だけで特定記事に帰属させない。固定コード付きURLを共有した読者もそのコードに分類されるため、**実際にその記事を読んだ個人を証明するものではない**。ブラウザの保存領域を使わず、複数日・複数端末の接点や全記事の経路を追う機能ではない。JS無効・準備前の即時クリック等は識別されない場合がある。元の広告リンクは使える。

## 発生から承認までの確認手順

1. 認証済みA8管理画面の「レポート → パラメータ計測」を開く。対象期間とプログラムをそろえ、id2=difyhost、id1で上の2記事を区別する。
2. 公式の項目説明に沿い、注文ID・注文日・確定日・ステータス・各パラメータ・報酬額を私有の台帳に記録する。A8で表示された内容だけを採用する。公開リポジトリへ会員向け財務情報や注文IDを入れない。
3. 同じプログラム・注文IDの状態を次回照合する。未確定から確定へ変わった行は更新し、発生と承認を別の注文として二重に足さない。キャンセルは別欄とし、未確定を否認扱いしない。
4. 記事ごとに、発生件数/額、未確定件数/額、確定件数/額、キャンセル件数を分ける。確定率は `確定 / (確定 + キャンセル)`、未確定を分母に入れない。分母0は未算出。承認日数は注文日から確定日までの実績とする。
5. 目標粗利には判定日を含む直近30日の**確定日**が期間内の確定売上を用いる。発生日別の獲得成績は別表。新規のサイソク拡大費を差し引き、既存共用ツールの配賦は引かない。入金日も別管理。

公式項目説明：[パラメータ計測レポート](https://support.a8.net/a8/as/faq/2025/post_2611.html)。この実装はA8帳票に分類を渡すもので、A8からの自動取込・承認通知・成果保証ではない。データのない画面からCSV列を推定して取込機能を作っていない。初回の自然な成果が入ったら実帳票の列・コード・報酬条件を照合してから自動化を検討する。

既存の `python3 scripts/aff_stats.py --date YYYY-MM-DD --json` で閲覧と比較への遷移を読む。独自計測の推定読者とA8注文は個人IDで結合しない。期間・対象・欠測が異なるので、表示数→閲覧→比較→注文の各値を同一人物の確定した流れと呼ばない。閲覧側の定義は `docs/dify-measurement-v2-20261030.md`。

## 検索記事の変更

- 費用記事：公式Model Providers資料に基づき、APIキーなしで試せる条件と `Integrations > Model Provider → Usage Priority` の確認場所を追加。
- 起動記事：公式資料に基づき、agent_backend/local_sandboxの再起動、docker/.envの場所のFAQを追加。実機で再現したとは書かない。
- 両記事の `refreshMode: editorial` を明示し、自動更新による手動原稿の上書きを防ぐ。タイトル・description・URL・公開日時は維持。
- 旧 `/compare/vps-dify-n8n` の2GB一括推奨を訂正。Dify公式の2コア/4GiBとXServerの4GB以上を案内し、n8nの必要量は用途によることを分ける。既存価格・広告・noindexは維持し、2記事への事前確認リンクを追加。
- `/guides`、比較ページから2記事への通常リンク、2記事の相互リンクは既に存在する。Google未登録を発見経路欠落と決めつけず、登録状況と検索実績を別に確認する。同一URLの登録申請を連打しない。

`node scripts/test_aff.mjs` は元URL保持、公式idの衝突、限定した対象、無料選択、DNT/GPC、query変更と解除、既存API・閲覧計測を外部広告通信なしで検査する。モックDOMの検査であり、実A8の注文・承認は再現しない。Reactの依存値、Suspense、解除処理、SSRの元リンク、外部通信の追加なしも点検する。
