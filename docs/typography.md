# 文字の読みやすさのルール（サイソク）

「文字が細すぎて見えない」「タイトルが小さくて自信がなさそうに見える」という指摘（2026-10-27）を受けて決めた、
サイト全体の文字のルール。感覚ではなく数字で決め、`scripts/check_readability.mjs` が実ページで毎回確かめる。

濃く・大きくすれば良いわけではない。**読む人が迷わず読めること**と、**情報の強弱（階層）がひと目でわかること**の両方を満たす。

## 根拠

| 根拠 | 使っている数字 |
| --- | --- |
| WCAG 2.2 達成基準 1.4.3（AA） | 文字と背景のコントラスト比 4.5:1 以上 |
| WCAG 2.2 達成基準 1.4.6（AAA） | 7:1 以上（説明文・補足に採用） |
| デジタル庁デザインシステム（タイポグラフィ） | 本文・UI は 16px 以上が基準。14px は補足・フッターなどの代替。14px 未満は原則不可。本文書体は Noto Sans JP。行間は本文 1.5 倍以上（1.7 前後）、見出しは 1.4〜1.5。字間は 26px 以下で 0.02em |
| 和文組版の慣習 | 1 行は全角 35〜40 字程度。長い文章は詰め組み（palt）にしない |
| 処理流暢性（processing fluency）の研究 | 読みやすく階層のはっきりした文字ほど「正しい・信頼できる」と受け取られやすい。書体だけで同じ文の信じられやすさが変わったという実験（Baskerville の実験）もある。小さく細い題名は自信がなく見える |

## 1. 書体

- 書体の順番: `Hiragino Sans` → `Hiragino Kaku Gothic ProN` → **Noto Sans JP**（Web フォント）→ `BIZ UDPGothic` → `Meiryo`。
  Apple の端末は内蔵のヒラギノで表示し、日本語の Web フォントを読み込まない（ホームで 2,733KB → 38KB、2026-10-28 計測）。
  ヒラギノが無い Windows・Android は **Noto Sans JP**（`app/fonts.ts`、可変フォント 1 本で 400〜900）で表示する。どちらも線がしっかりしていて小さくてもかすれない
- Noto Sans JP が届くまでの代わり: `BIZ UDPGothic` → `Meiryo`。
  **游ゴシック（Yu Gothic）は入れない**（Windows の Regular は線が細くかすれる）
- 旧 Zen Kaku Gothic New は 400 の線が細く「見えない」ため廃止
- Dela Gothic One はロゴ「サイソク」だけ。Martian Mono は時刻・件数など小さな数字だけ
- 1 ページの中で書体を増やさない（ページ単位で別の書体スタックを指定しない）

## 2. 文字サイズ（役割で選ぶ。px を直接書かない）

| 役割 | クラス | 大きさ | 使う場所 |
| --- | --- | --- | --- |
| 記事本文 | `.prose` | スマホ 16px / PC 17px | 記事の段落・箇条書き |
| 説明文・リード | `text-desc` / `t-lead` | 16px（`t-lead` は PC 17px） | 題名の下の説明、カードの要約、40 字以上の文章 |
| 注記 | `text-note` | 14px | 出典・免責・注意書き・表のセル・フッターのリンク |
| ラベル | `text-meta` | 13px | 日付・件数・分類など短いラベル（1 行・おおむね 20 字以内） |
| バッジ | `text-badge`（`.eyebrow`） | 12px | 角丸の札（「更新」「PR」「まとめ」など数文字）だけ |

- **12px 未満は使わない**。12px はバッジだけ
- **40 字以上の文章は 16px 以上**（注記として `text-note` を付けたものだけ 14px 可）
- 写真の代わりの図版（`Thumb` の代替表示、企業の色見本 `CompanyMark`、`role="img"` の商品図）は文字ではなく画像として扱い、
  `data-decorative` を付けて対象外にする

## 3. 太さ

- 本文・説明文 400、ラベルも 400 以上。**300 以下（細字）は使わない**
- 強調 700、カードの題名 700、見出し 700〜900（h1 は 900）

## 4. コントラスト（ライト・ダーク両方）

| 対象 | 下限 | 今の値（ライト / ダーク） |
| --- | --- | --- |
| 記事本文 `--ink-soft` | 10:1 | 11.3:1 / 11.8:1 |
| 説明文・補足 `--muted` | 7:1 | 7.9:1（灰地 7.1:1）/ 8.3:1（カード地 7.6:1） |
| どんな文字も | 4.5:1 | リンク `--accent` 5.5:1 / 10:1 |

- **段落に `text-muted` を使わない**（`muted` は日付・件数などのラベルだけ）
- 赤地（`bg-live`）の文字は `text-live-ink`（ライトは白、ダークは紺）。白固定にしない
- 企業の色を文字色に使わない（色は線・点・色見本で示し、文字は `text-ink`）

## 5. 見出しの型（自信のある見え方）

| 型 | スマホ | PC（1024px〜） | 太さ | 行間 | 使う場所 |
| --- | --- | --- | --- | --- | --- |
| `t-h1` | 30px | 44px（640px〜は 38px） | 900 | 1.35 | ページ・記事の題名（h1） |
| `t-h2` | 23px | 28px（640px〜は 26px） | 800 | 1.45 | ページの節（h2）。記事本文の h2 も同じ大きさ |
| `t-h3` | 20px | 20px | 700 | 1.5 | 枠の見出し（目次・要点・判断）、小見出し |
| `t-card` | 17px | 18px | 700 | 1.55 | 一覧の記事・製品の題名 |

- **本文との大きさの比**: h1 は本文の 1.8 倍以上（スマホ）・2.5 倍以上（PC）。記事本文の中の h2 は 1.35 倍以上
- 題名を灰色にしない。極端に小さい見出し（13px の太字ラベルを h2 にする等）にしない。字間を広げすぎない（見出しは 0〜-0.01em）
- 長い題名は `text-wrap: balance`、記事の題名は `.headline`（文節の切れ目で改行）

## 6. 行間・字間・1 行の長さ

- 本文 1.9、説明文 1.75〜1.9、見出し 1.35〜1.5
- 字間 0〜0.04em（記事本文 0.02em）。長い文章（`.prose` の段落・`text-desc`・`t-lead`）は詰め組み（palt）を切る
- 1 行は全角 40 字まで（記事本文は `max-w-[40em]`、リードは `t-lead` が 40em）

## 機械チェック

```sh
npm run check:readability                                  # 本番（https://ai-tech-express.jp）
npm run check:readability -- --base http://localhost:3100  # 手元（next dev -p 3100 など。3000 番は別のプロジェクト）
npm run check:readability -- --paths /,/products --shots out/readability/shots --full
```

375px / 1440px × ライト / ダークで主要ページを開き、見えている文字をすべて調べる。違反があれば終了コード 1。
判定の数字は `scripts/check_readability.mjs` の `RULES`（この文書と同じ数字）。

- 13px 未満（バッジ 12px 未満）／太さ 400 未満／コントラスト 4.5:1 未満
- 40 字以上の細字のブロック: 16px 未満（注記 14px 未満）／コントラスト 7:1 未満
- 記事本文: 16px（PC 17px）未満／コントラスト 10:1 未満
- h1: 28px（PC 36px）未満、本文の 1.8 倍（PC 2.5 倍）未満、太さ 700 未満、コントラスト 7:1 未満
- h2: 20px 未満、記事本文中は本文の 1.35 倍未満／h3: 17px 未満
- 画像の上の文字はコントラストを測れないので件数だけ出す（目視で確認）

GitHub Actions の「Readability check」が、人の push で走ったデプロイの後に本番へ同じチェックをかける。
