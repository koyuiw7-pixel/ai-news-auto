# 通常SNS投稿の403修正（2026-10-30）

## 原因と変更

通常投稿の `scripts/threads_post.py:wait_until_live` は、UA未指定のHEADで記事の公開を確認していた。CloudflareのBrowser integrity checkがPython標準UAを403/1010で遮断するため、公開済みでも最大600秒後に未公開扱いで投稿を見送っていた。

根拠: Actions run 40926777982 の10/30 03:29:45 JSTのskipと、同時刻・同URL・HEAD・Python-urllib/3.12のCloudflare遮断記録。対象は `hugging-face-any-speech-decision-apple`。

この通信に `SaisokuPublishCheck/1.0 (+https://ai-tech-express.jp)` を付ける。200だけを成功とする判定、HEAD、20秒の通信タイムアウト、15秒の再確認間隔、全体の待機上限は維持。Cloudflareの保護設定は変更しない。

投稿文・投稿枠・1日の本数・A/B比較・広告リンク・地震処理・速報投稿・重複防止履歴も変更しない。速報用の `breaking_post.py` は別経路なので、全SNS停止の修正ではない。

復旧確認用に `.github/workflows/sns_recover.yml` を追加。手動実行のみで、既存の通常投稿スクリプトと本数設定を使う。記事生成・LLM・新しい定期実行は追加しない。auto_runと同じ排他グループで重複実行を防ぎ、今回追加した投稿履歴だけを最新mainへ足す。既存履歴や同時更新された計測値を上書きしない。
