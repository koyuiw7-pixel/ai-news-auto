## イベントと互換性

- `article_view`：対象2記事が可視状態で1秒経過した場合。1秒未満でも、可視中に比較ページへの信頼されたクリックがあれば閲覧として先に送る。
- 対象2記事の `article_view` と既存 `guide_click` に `articleMeasurement: 2` を付ける。旧クライアントの `guide_click` にはこのマーカーがないため、新しい閲覧分母には混ぜない。
- 1ページ滞在中の同種・同行き先の送信を1回に抑える。Beaconのキュー登録が失敗した場合は送信済みとしない。早いクリックで閲覧の送信だけが失敗した場合、遷移を妨げず、後続の可視タイマーで再試行できる間だけ再試行する。
- 非表示中の対象記事からのクリック、信頼されないクリック、右クリックでは追加計測しない。
- 既存の `entry_view`、`guide_click`、`guide_view`、`comparison_view`、`choice_click` の意味と集計を維持。旧広告の `c:` キー、リンク先、計測タグ、配置別集計も維持する。
- APIの `funnel.version` は2。従来のフィールドは残し、`stages` に `article_view` を追加する。旧JSONを読むPython表示処理にも対応する。
- 対象外パス、クエリ文字列、誤ったv2マーカー、許可外の流入元などは受け付けない。

## 記事別集計の読み方

`funnel.articleMeasurement.byArticle` は対象記事別、`byArticleSource` は記事と流入元の組み合わせ別。日付はAPIで指定した日本時間の1日。

| 項目 | 意味 |
|---|---|
| `observedV2Events` | その集計区分で観測したv2閲覧とv2比較クリックのイベント合計 |
| `viewEvents` / `viewVisitors` | 可視閲覧イベント数／同日の推定読者数 |
| `comparisonClickEvents` / `comparisonClickVisitors` | 比較リンクのv2クリック数／同日の推定読者数 |
| `matchedReaderClickVisitors` | 同じ集計区分で閲覧とクリックの両方を観測した日内推定読者数 |
| `clickVisitorsWithoutObservedView` | クリックは観測したが、同じ区分の閲覧を観測できなかった日内推定読者数 |
| `observedReaderClickRate` | 双方観測した推定読者数 ÷ 閲覧を観測した推定読者数。分母0は `null` |
| `legacyClickEventsExcluded` | 記事別の新計測から除外した旧 `guide_click` の件数。旧 `byEntry` 等には引き続き含む |

推定読者の突合には既存の日次IP/UAハッシュを使う。新しい個人識別子、長期追跡ID、検索語、参照元URL全文は追加しない。別端末では同じ人が別になり、同じ接続環境の複数人が同じものになる場合がある。

この割合は**順序付きセッションのCVRではない**。閲覧とクリックが同じページ滞在中だったことや、その順序、比較先への実到達、契約・承認を証明しない。流入元が違う場合、記事全体では双方を観測しても、流入元別では突合されない場合がある。比較ページの表示・行き先選択・広告主の成果は、それぞれ別の指標として確認する。

## 移行と欠測

- 導入前の入口記事の閲覧は、この専用計測からは復元できない。別Analyticsに記事別閲覧があるかは別に確認する。
- 導入日は途中からの計測で、古いクライアントを開いている閲覧者もいる。旧クリックをv2閲覧の分母と混ぜない。
- `observedV2Events: 0` は「対象イベントを観測していない」であり、全訪問0の証明ではない。分母がない割合を0%に置き換えない。
- Beaconの失敗、ページ離脱、ブロッカー、DNT/GPC、重複抑制、集計上限、保存・送信の遅延による欠測があり得る。クリックが先に到着した時点では閲覧未観測として表示し、閲覧が到着した後の再集計で突合される。
- 日をまたぐ閲覧とクリックは同じ日に突合しない。日次推定人数を日をまたいで加算してユニーク人数と呼ばない。
- 新旧の数字、Search Console、Web Analytics、広告主画面は期間・対象・除外条件が違うため、そのまま率を作らない。

## プライバシー・既存機能

既知のボット、検査ツール、自動ブラウザ、DNT/GPCの除外を維持。集計は同一オリジン限定で、認証付きの読み取りを維持する。可視閲覧・遷移の記録は90日、旧広告クリックは400日保持。既存の日次ハッシュ・短時間の流入元分類保存の範囲を広げていない。

広告クリックと導線イベントの連投制限は別枠。新しい閲覧イベントが旧広告クリックの制限枠を消費しない。計測に失敗しても記事の表示やリンク遷移を止めない。

主な確認内容：同一オリジン・認証、ボット/DNT/GPC除外、保存項目と保持期間、旧広告クリック互換、無料/有料の分離、対象2記事と流入元の分離、新旧クリック混在、1秒前のクリック、二重計測、閲覧Beacon失敗、到着順逆転、日跨ぎ、イベント解除。

APIテストはメモリーKV、クライアントテストはモックDOMとBeaconを使用する。クライアントのイベント処理そのものを実行するが、Reactのマウントや本番ブラウザ表示を再現する検査ではない。実ASP、本番KV、外部ネットワークへの書き込みは行わない。本番に自己イベントや広告クリックを入れて数字を作らない。

通常ビルド、既存表示検査、デプロイ成功、本番コードと認証付き読み取りの確認は、反映担当の記録を別に追記する。ローカル30項目の成功だけを本番反映完了や実読者の増加と扱わない。

## ロールバック

反映担当が確定した計測変更コミットをrevertし、通常のビルド・デプロイ・既存計測の確認を行う。目標定義の更新まで戻る場合は、オーナーが確定した利益の定義を保持する。既存KVや投稿履歴は削除しない。

v2の `article_view` は旧コードの集計対象外となるが、記録は保持期限まで残る。`guide_click` は旧形式の集計に引き続き含まれる。古い画面コードと新しいサーバー、またはその逆が一時的に混在するため、移行中の欠測を確定的な訪問減と扱わない。新しい閲覧イベントの拒否が発生しても、記事表示や比較への遷移は止まらない。
